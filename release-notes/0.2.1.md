# Bedrock 0.2.1

## Highlights

- `bedrock.contrib.storage` is a stable synchronous, provider-neutral object-storage API. It includes a local backend and optional S3 support.
- `bedrock.contrib.metrics` is a stable, stateless `count`/`gauge` API. Calls are structured log events and can be forwarded to a custom `MetricsProvider`.
- `bedrock-core`, `bedrock-cli`, and the storage and metrics contrib manifests are aligned at `0.2.1`.

## Installation and optional extras

Install the core runtime with `pip install bedrock-core`. The local storage backend is included. Install S3 support with `pip install 'bedrock-core[storage-s3]'`; credentials are resolved through boto3's standard provider chain. The existing Redis cache extra remains `bedrock-core[cache-redis]`.

## Upgrade notes

Storage callers should use relative POSIX keys and the `StoredFile` metadata returned by `put` and `head`. The local backend rejects path traversal and does not expose signed URLs. S3 supports signed download URLs; configure its bucket and optional endpoint settings before use.

Metrics does not aggregate values in process. Treat `count` as an increment event and `gauge` as an observation. Configure a `MetricsProvider` when events must be exported; the default is validation and structured logging only. Provider failures are fail-open by default and become exceptions only in strict mode.

## Known limitations

- Storage does not include multipart upload, directory listing, public URL configuration, version management, or cross-backend transfers.
- S3 `copy(..., overwrite=False)` has a preflight race; use `put(..., overwrite=False)` when strict create-only behavior is required.
- No Prometheus, OpenTelemetry, or StatsD exporter is bundled for metrics.
- `bedrock-cli` remains an evolving scaffolding surface; pin the 0.2 release line when generated output must be reproducible.
